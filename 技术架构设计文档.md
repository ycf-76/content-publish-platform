## 1. 设计目标

1. **编排/执行/能力三层解耦**：LangGraph管流程，Harness管Agent运行时，Skills+MCP管能力。
2. **配置驱动**：新增Agent = 加一份YAML配置 + 可能加一个Skill，不动编排代码。
3. **可观测可调试**：每个Agent调用可追踪，每个checkpoint可恢复。
4. **可替换**：LLM、生图模型、MCP服务均通过适配器接入，换实现不影响上层。

---

## 2. 三层架构总览

```
┌─────────────────────────────────────────────────────────────────┐
│                     Layer A: 编排层 (LangGraph)                  │
│  StateGraph / conditional edges / interrupt / checkpoint        │
│  职责: 节点拓扑、状态流转、回退、人工审核暂停-恢复              │
│  ┌─────────────────────────────────────────────────────────┐    │
│  │  Layer B: 执行层 (自研Harness)                          │    │
│  │  每个graph node = 一个Harness实例                        │    │
│  │  职责: LLM调用、Skills调度、硬规则guard、软语义触发      │    │
│  │  ┌─────────────────────────────────────────────────┐    │    │
│  │  │  Layer C: 能力层 (Skills + MCP)                  │    │    │
│  │  │  @tool本地函数 / MCP服务调用                      │    │    │
│  │  │  职责: 具体能力实现(搜索/生图/VL/发布)            │    │    │
│  │  └─────────────────────────────────────────────────┘    │    │
│  └─────────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────────┘
```

| 层 | 技术 | 关注点 | 不可越界 |
|---|---|---|---|
| A 编排 | LangGraph | 谁先跑、状态、回退、暂停 | 不关心Agent内部怎么跑 |
| B 执行 | 自研Harness | LLM+Skills+guard+软语义 | 不关心能力是本地函数还是MCP |
| C 能力 | Skills+MCP | 具体API调用 | 不关心被谁调用 |

## 3. Layer A：LangGraph 编排层

### 3.1 State 定义

```python
from typing import TypedDict, Literal
from pydantic import BaseModel

class NodeOutput(BaseModel):
    """单个节点的标准化产出"""
    status: Literal["passed", "error", "awaiting_review"]
    data: dict                          # 业务产出
    quality_report: dict | None = None  # 软语义报告
    error: str | None = None
    model: str | None = None
    token_cost: int = 0

class WorkflowState(TypedDict):
    """LangGraph全局State，跨节点共享"""
    workflow_id: str
    theme: str
    keyword: str | None
    account_id: str

    # 各节点的产出（按node_type为key）
    outputs: dict[str, NodeOutput]

    # 监督Agent分散式守卫的决策记录
    supervisor_decisions: list[dict]

    # 人工审核结果（通过interrupt注入）
    human_reviews: dict[str, dict]  # {"image_review": {"action": "pass"}, ...}

    # 当前阶段
    current_node: str
    error: str | None
```

### 3.2 Graph 拓扑定义

```python
from langgraph.graph import StateGraph, END
from langgraph.checkpoint.postgres import PostgresSaver

def build_workflow_graph(checkpointer: PostgresSaver):
    graph = StateGraph(WorkflowState)

    # === 注册业务节点（每个节点 = 一个Harness调用） ===
    graph.add_node("search",       search_harness_node)
    graph.add_node("analyze",      analyze_harness_node)
    graph.add_node("image_gen",    image_gen_harness_node)
    graph.add_node("image_review", image_review_node)        # 人工审核，interrupt
    graph.add_node("copywrite",    copywrite_harness_node)
    graph.add_node("audit",        audit_harness_node)
    graph.add_node("final_review", final_review_node)        # 人工终审，interrupt
    graph.add_node("publish",      publish_harness_node)

    # === 注册软语义判断节点（分散式守卫的Layer2） ===
    graph.add_node("analyze_quality_check",   make_quality_check_node("analyze"))
    graph.add_node("copywrite_quality_check", make_quality_check_node("copywrite"))
    graph.add_node("audit_quality_check",     make_quality_check_node("audit"))

    # === 边：主流程 ===
    graph.set_entry_point("search")
    graph.add_edge("search", "analyze")
    graph.add_edge("analyze", "analyze_quality_check")
    graph.add_edge("image_gen", "image_review")
    graph.add_edge("image_review", "copywrite")
    graph.add_edge("copywrite", "copywrite_quality_check")
    graph.add_edge("audit", "audit_quality_check")
    graph.add_edge("final_review", "publish")
    graph.add_edge("publish", END)

    # === 边：质量检查 → 路由（Layer3状态机硬编码） ===
    graph.add_conditional_edges(
        "analyze_quality_check",
        route_by_quality,
        {"pass": "image_gen", "suggest_rollback": "analyze"}
    )
    graph.add_conditional_edges(
        "copywrite_quality_check",
        route_by_quality,
        {"pass": "audit", "suggest_rollback": "copywrite"}
    )
    graph.add_conditional_edges(
        "audit_quality_check",
        route_by_quality,
        {"pass": "final_review", "suggest_rollback": "copywrite"}
    )

    # === interrupt：人工审核节点 ===
    # image_review 和 final_review 在执行前暂停，等待用户审核
    # 通过 Command(resume=...) 恢复

    return graph.compile(
        checkpointer=checkpointer,
        interrupt_before=["image_review", "final_review"]
    )
```

### 3.3 路由函数（Layer3 硬编码）

```python
def route_by_quality(state: WorkflowState) -> str:
    """
    Layer3状态机：根据软语义判断结果硬编码路由
    LLM不参与跳转决策
    """
    current = state["current_node"]
    quality = state["outputs"].get(current.replace("_quality_check", ""))
    if quality and quality.quality_report:
        if quality.quality_report.get("quality_pass", True):
            return "pass"
        else:
            # 软语义不通过 → 生成"建议回退"指令（建议权）
            # 不直接回退，前端弹确认框让用户拍板
            return "suggest_rollback"
    return "pass"
```

### 3.4 回退实现（LangGraph原生）

```python
async def rollback_to_node(workflow_id: str, target_node: str, db_session):
    """
    回退到指定节点的checkpoint，下游重跑（D6语义）
    利用LangGraph原生checkpoint恢复机制
    """
    # 1. 查找目标节点对应的checkpoint
    target_checkpoint = await find_checkpoint(workflow_id, target_node, db_session)
    if not target_checkpoint:
        raise ValueError(f"No checkpoint found for {target_node}")

    # 2. 用LangGraph的thread_id + checkpoint_id恢复
    config = {
        "configurable": {
            "thread_id": workflow_id,
            "checkpoint_id": target_checkpoint.langgraph_checkpoint_id
        }
    }

    # 3. 重新invoke，从target_node开始往后重跑
    # 下游节点的旧产出会被新执行覆盖（LangGraph语义）
    graph = get_compiled_graph()
    result = await graph.ainvoke(None, config=config)  # None表示从checkpoint恢复
    return result
```

```python
async def resume_after_review(workflow_id: str, node: str, review_result: dict):
```

## 4. Layer B：自研 Harness 架构（子包，非单文件）

Harness 不是单个 class，而是 Agent 的**运行时框架**，由多个子系统组成。本章描述4个子系统：Runtime（入口）、Executor（执行循环）、Recovery（恢复子系统，含智能退避+熔断）、Observer（观测）。Lifecycle/Context/Tool Dispatcher/Hooks 因当前6个Agent都是单轮固定流程，暂不实现，二期按需补。

### 4.1 Harness 子系统总览

```
agents/harness/
├── runtime.py              # 1. Runtime：harness入口，组装各子系统
├── executor/               # 2. Executor：执行循环（可插拔）
│   ├── base.py
│   └── single_shot.py      #    单轮执行器（6个Agent当前都用它）
├── recovery/               # 3. Recovery：恢复子系统（★监督-修复循环核心）
│   ├── loop.py             #    RecoveryLoop：有限次重试循环
│   ├── strategies.py       #    RecoveryStrategy：可插拔策略
│   ├── backoff.py          #    智能退避（指数退避+抖动）
│   ├── circuit_breaker.py  #    熔断器
│   └── supervisor.py       #    监督Agent恢复决策（跨节点回退）
└── observer.py             # 4. Observer：trace/metrics/logs
```

### 4.2 Runtime（harness入口）

```python
from abc import ABC, abstractmethod

class AgentHarness(ABC):
    """
    Harness入口，组装各子系统
    每个 Agent = 一个Harness子类 + 一份YAML配置
    """

    def __init__(
        self,
        agent_id: str,
        role: str,
        llm: BaseLLM | None,
        skills: list[Skill],
        prompt_template: PromptTemplate | None,
        output_schema: type[BaseModel],
        hard_rules: list[HardRule],
        soft_semantic_config: SoftSemanticConfig | None,
        executor: ExecutorBase,                      # ★ 注入执行器
        recovery_loop: RecoveryLoop,                 # ★ 注入恢复循环
        observer: Observer,
    ):
        self.agent_id = agent_id
        self.role = role
        self.llm = llm
        self.skills = skills
        self.prompt_template = prompt_template
        self.output_schema = output_schema
        self.hard_rules = hard_rules
        self.soft_semantic_config = soft_semantic_config
        self.executor = executor
        self.recovery_loop = recovery_loop
        self.observer = observer

    async def run(self, input: dict, context: WorkflowState) -> NodeOutput:
        """
        标准执行流程：
        1. 前置硬规则guard
        2. 委托 executor 执行（执行内部由 recovery_loop 包裹恢复循环）
        3. 后置硬规则guard（schema校验）
        4. 软语义由编排层的quality_check_node触发，不在Harness内
        """
        # --- Layer1: 前置硬规则 ---
        for rule in self.hard_rules:
            if not rule.pre_check(input, context):
                await self.observer.log_pre_check_fail(self.agent_id, rule.name)
                return NodeOutput(status="error", data={}, error=f"Pre-check failed: {rule.name}")

        # --- 执行 + Recovery Loop 包裹 ---
        try:
            raw_output = await self.recovery_loop.execute_with_recovery(
                agent=self,
                input=input,
                context=context,
                execute_fn=lambda inp, ctx: self.executor.execute(
                    agent_id=self.agent_id,
                    llm=self.llm,
                    skills=self.skills,
                    prompt_template=self.prompt_template,
                    output_schema=self.output_schema,
                    input=inp,
                    context=ctx,
                    _execute_impl=self._execute,  # 委托给子类的具体逻辑
                )
            )
        except RecoveryExhaustedError as e:
            # Recovery Loop 三次策略全失败 → 上报监督Agent（见6.3）
            await self.observer.log_recovery_exhausted(self.agent_id, e)
            return NodeOutput(
                status="error",
                data={},
                error=f"Recovery exhausted: {e}",
                escalate_to_supervisor=True   # ★ 触发监督Agent介入
            )

        # --- 后置硬规则：schema校验 ---
        try:
            validated = self.output_schema.model_validate(raw_output)
        except ValidationError as e:
            await self.observer.log_schema_fail(self.agent_id, e)
            return NodeOutput(status="error", data={}, error=f"Schema: {e}")

        return NodeOutput(
            status="passed",
            data=validated.model_dump(),
            model=self.llm.model_name if self.llm else None,
            token_cost=getattr(raw_output, "usage", 0)
        )

    @abstractmethod
    async def _execute(self, input: dict, context: WorkflowState) -> dict:
        """子类实现具体业务逻辑：组装prompt、调用LLM、调度Skills"""
        pass
```

### 4.3 Executor（执行循环，可插拔）

```python
from abc import ABC, abstractmethod

class ExecutorBase(ABC):
    """执行器接口：定义Agent怎么跑（单轮/ReAct/Plan-Execute）"""

    @abstractmethod
    async def execute(self, agent_id, llm, skills, prompt_template,
                      output_schema, input, context, _execute_impl) -> dict:
        pass

class SingleShotExecutor(ExecutorBase):
    """
    单轮执行器：一次LLM调用 + 固定Skills调用流程
    当前6个Agent都用它（搜索/分析/图片/文案/审核/发布）
    二期若有Agent需要ReAct，新增 ReactExecutor 即可，不动其他代码
    """

    async def execute(self, agent_id, llm, skills, prompt_template,
                      output_schema, input, context, _execute_impl) -> dict:
        # 超时控制（15s，硬规则）
        return await asyncio.wait_for(
            _execute_impl(input, context),
            timeout=15
        )
```

### 4.4 Recovery 子系统（★监督-修复循环核心）

这是 harness 架构里最关键的子系统，解决你提出的"监督者发现崩溃→重新执行"的循环需求。不是 ReAct（不重新思考），而是"带策略切换的有限次重试 + 熔断 + 监督介入"。

#### 4.4.1 RecoveryLoop（恢复循环）

```python
class RecoveryLoop:
    """
    每个Agent内部的恢复循环
    - max_attempts=3（决策锁定）
    - 配合智能退避 + 熔断器
    - 三次策略全失败 → 上报监督Agent（不继续死循环）
    """

    def __init__(
        self,
        max_attempts: int,             # =3
        strategies: list[RecoveryStrategy],  # 按顺序尝试的策略
        backoff: BackoffPolicy,        # 退避策略
        circuit_breaker: CircuitBreaker,  # 熔断器
        observer: Observer,
    ):
        self.max_attempts = max_attempts
        self.strategies = strategies
        self.backoff = backoff
        self.circuit_breaker = circuit_breaker
        self.observer = observer

    async def execute_with_recovery(self, agent, input, context, execute_fn) -> dict:
        """
        恢复循环主流程
        每次attempt使用一个strategy调整输入/参数，然后执行
        """
        # 熔断器：如果该Agent最近失败率过高，直接拒绝执行
        if not self.circuit_breaker.allow_request(agent.agent_id):
            await self.observer.log_circuit_open(agent.agent_id)
            raise RecoveryExhaustedError(f"Circuit open for {agent.agent_id}")

        last_error = None
        for attempt, strategy in enumerate(self.strategies[:self.max_attempts]):
            try:
                # 策略调整输入/参数（如拓宽关键词、换模型、减少输入量）
                adjusted_input, adjusted_ctx = strategy.adjust(input, context)

                await self.observer.log_attempt(
                    agent_id=agent.agent_id,
                    attempt=attempt,
                    strategy=strategy.name,
                    adjusted=True
                )

                # 执行
                result = await execute_fn(adjusted_input, adjusted_ctx)

                # 成功 → 记录成功，熔断器记录成功
                self.circuit_breaker.record_success(agent.agent_id)
                return result

            except (asyncio.TimeoutError, ValidationError, HTTPError, CrashError) as e:
                last_error = e
                await self.observer.log_attempt_failed(
                    agent_id=agent.agent_id,
                    attempt=attempt,
                    strategy=strategy.name,
                    error=str(e)
                )

                # 熔断器记录失败
                self.circuit_breaker.record_failure(agent.agent_id)

                # 智能退避：不是立刻重试
                if attempt < self.max_attempts - 1:
                    delay = self.backoff.next_delay(attempt)
                    await asyncio.sleep(delay)

                continue  # 试下一个策略

        # 三个策略全失败
        raise RecoveryExhaustedError(
            f"Agent {agent.agent_id} recovery exhausted after {self.max_attempts} attempts. "
            f"Last error: {last_error}"
        )
```

#### 4.4.2 智能退避（BackoffPolicy）

```python
import random

class BackoffPolicy:
    """
    智能退避：指数退避 + 抖动
    避免雪崩式重试打爆下游服务
    """

    def __init__(self, base_delay: float = 1.0, max_delay: float = 30.0, jitter: bool = True):
        self.base_delay = base_delay
        self.max_delay = max_delay
        self.jitter = jitter

    def next_delay(self, attempt: int) -> float:
        """attempt从0开始，delay = base * 2^attempt + jitter"""
        delay = min(self.base_delay * (2 ** attempt), self.max_delay)
        if self.jitter:
            delay += random.uniform(0, delay * 0.1)  # 0-10%抖动
        return delay
```

#### 4.4.3 熔断器（CircuitBreaker）

```python
from enum import Enum
from time import time

class CircuitState(Enum):
    CLOSED = "closed"      # 正常，放行
    OPEN = "open"          # 熔断，拒绝
    HALF_OPEN = "half_open"  # 半开，试探放行一个

class CircuitBreaker:
    """
    熔断器：防止崩溃Agent被反复重试拖垮系统
    基于滑动窗口失败率
    """

    def __init__(
        self,
        failure_threshold: int = 5,       # 窗口内5次失败触发熔断
        recovery_timeout: float = 60.0,   # 熔断60秒后半开试探
        half_open_max: int = 1,           # 半开态最多放行1个
    ):
        self.failure_threshold = failure_threshold
        self.recovery_timeout = recovery_timeout
        self.half_open_max = half_open_max
        self.states: dict[str, CircuitState] = {}      # agent_id → state
        self.failure_counts: dict[str, int] = {}
        self.last_failure_time: dict[str, float] = {}
        self.half_open_inflight: dict[str, int] = {}

    def allow_request(self, agent_id: str) -> bool:
        state = self._get_state(agent_id)
        if state == CircuitState.CLOSED:
            return True
        if state == CircuitState.OPEN:
            # 检查是否到了半开时间
            if time() - self.last_failure_time[agent_id] > self.recovery_timeout:
                self.states[agent_id] = CircuitState.HALF_OPEN
                self.half_open_inflight[agent_id] = 0
                return True
            return False  # 熔断中，拒绝
        if state == CircuitState.HALF_OPEN:
            # 半开态只允许有限试探
            if self.half_open_inflight.get(agent_id, 0) < self.half_open_max:
                self.half_open_inflight[agent_id] += 1
                return True
            return False

    def record_success(self, agent_id: str):
        self.failure_counts[agent_id] = 0
        self.states[agent_id] = CircuitState.CLOSED
        self.half_open_inflight[agent_id] = 0

    def record_failure(self, agent_id: str):
        self.failure_counts[agent_id] = self.failure_counts.get(agent_id, 0) + 1
        self.last_failure_time[agent_id] = time()
        if self.failure_counts[agent_id] >= self.failure_threshold:
            self.states[agent_id] = CircuitState.OPEN
            # 触发告警
            ...

    def _get_state(self, agent_id: str) -> CircuitState:
        return self.states.get(agent_id, CircuitState.CLOSED)
```

#### 4.4.4 Recovery Strategy（可插拔策略）

```python
from abc import ABC, abstractmethod
from dataclasses import dataclass

@dataclass
class RecoveryStrategy(ABC):
    """恢复策略接口：调整输入/参数后重试"""
    name: str

    @abstractmethod
    def adjust(self, input: dict, context: WorkflowState) -> tuple[dict, WorkflowState]:
        """返回调整后的(input, context)"""
        pass

# === 策略库（按需组合，每个Agent配不同策略） ===

class RetryStrategy(RecoveryStrategy):
    """策略1：原样重试（应对网络抖动等瞬时错误）"""
    name = "retry"
    def adjust(self, input, context):
        return input, context

class BroadenKeywordStrategy(RecoveryStrategy):
    """策略2：拓宽搜索关键词（应对搜索结果为空）"""
    name = "broaden_keyword"
    def adjust(self, input, context):
        new_input = {**input, "keyword": broaden(input["keyword"])}
        return new_input, context

class ReduceInputStrategy(RecoveryStrategy):
    """策略2'：减少输入量（应对输入过长导致LLM崩溃）"""
    name = "reduce_input"
    def __init__(self, max_items: int = 5):
        self.max_items = max_items
    def adjust(self, input, context):
        if "notes" in input:
            new_input = {**input, "notes": input["notes"][:self.max_items]}
            return new_input, context
        return input, context

class SimplifyPromptStrategy(RecoveryStrategy):
    """策略2''：简化prompt要求（应对R1因复杂要求崩溃）"""
    name = "simplify_prompt"
    def adjust(self, input, context):
        # 通过context标记，让executor使用简化版prompt
        new_ctx = {**context, "use_simplified_prompt": True}
        return input, new_ctx

class SwitchModelStrategy(RecoveryStrategy):
    """策略3：切换备用模型（应对模型过载/不可用）"""
    name = "switch_model"
    def __init__(self, fallback: str):
        self.fallback = fallback
    def adjust(self, input, context):
        # 通过context标记，让executor用fallback模型
        new_ctx = {**context, "force_model": self.fallback}
        return input, new_ctx
```

```python
                strategies.append(STRATEGY_REGISTRY[s]())

                name, params = next(iter(s.items()))
                strategies.append(STRATEGY_REGISTRY[name](**params))

        return RecoveryLoop(
            max_attempts=recovery_cfg["max_attempts"],
            strategies=strategies,
            backoff=BackoffPolicy(**recovery_cfg["backoff"]),
            circuit_breaker=CircuitBreaker(**recovery_cfg["circuit_breaker"]),
```

### 5.2 MCP 服务集成（D17 双模式 + 降级策略）

#### 5.2.1 双模式架构总览

小红书数据获取采用 **MCP服务化** 架构，两种启动方式分层互补，对Agent透明：

```
┌─────────────────────────────────────────────────────┐
│              FastAPI 后端（编排层）                   │
│                                                      │
│  ┌──────────────────────────────────────────────┐   │
│  │  MCP Client Manager（统一入口）               │   │
│  │  ├── search_notes(keyword, limit)            │   │
│  │  ├── fetch_post_detail(note_id)              │   │
│  │  ├── publish(content)                        │   │
│  │  └── get_login_status()                      │   │
│  │                                              │   │
│  │  策略: 优先插件 → 降级uv run                  │   │
│  └──────────────────────────────────────────────┘   │
│         │ SSE/HTTP                      │ stdio     │
└─────────┼────────────────────────────────┼──────────┘
          ▼                                ▼
┌──────────────────────┐          ┌──────────────────────┐
│ 方式A: 浏览器插件MCP  │          │ 方式B: uv run MCP    │
│ (xhs-mcp-server)     │          │ (mcp_fetch_xhs_post) │
│                      │          │                      │
│ 生产首选              │          │ 开发/兜底             │
│ 复用用户浏览器登录态   │          │ Playwright headless  │
│ 真实IP+真实浏览器     │          │ 服务器IP（风控高）    │
│ 风控最低              │          │ 需扫码拿Session       │
└──────────────────────┘          └──────────────────────┘
```

**两种方式定位**：

| 维度 | 方式A 浏览器插件 | 方式B uv run |
|---|---|---|
| 定位 | 生产环境首选 | 开发联调/兜底 |
| 风控 | 极低（真实浏览器+家庭IP+真实登录态） | 高（机房IP+headless特征） |
| 登录态 | 复用用户浏览器，无需扫码 | 需扫码拿Session注入Playwright |
| 签名 | 浏览器原生生成 | 浏览器原生生成（Playwright） |
| 用户门槛 | 需装插件（开发者模式加载crx） | 无需用户操作 |
| 传输协议 | SSE/HTTP（MCP标准） | stdio（MCP标准） |
| 故障影响 | 浏览器关了即不可用 | 服务器进程独立 |

**对Agent透明**：两种方式暴露**完全相同的MCP接口**，Skill层做统一抽象，Agent不关心底层是插件还是uv run。

#### 5.2.2 方式A：浏览器插件MCP（xhs-mcp-server）

**分发方式**：自建下载页，用户下载crx文件，Chrome开发者模式加载（D17决策）。

**通信架构**：
```
用户浏览器（已登录小红书）
    └── Chrome插件（xhs-mcp-server）
         ├── 监听Native Messaging / 本地WebSocket端口
         ├── 复用浏览器的Cookie/LocalStorage登录态
         ├── 操作当前页面DOM执行搜索/抓取
         └── 暴露MCP接口（SSE/HTTP）给后端调用
```

**核心优势**：
- 用户浏览器**本来就已登录小红书**，插件直接复用，**无需额外扫码**（这是对D1的重要简化）
- 真实用户行为特征（鼠标轨迹、滚动节奏、IP），风控最低
- 配图可直接从DOM截取/下载

**插件实现要点**：
- background service worker：维持MCP server，监听后端调用
- content script：注入小红书页面，执行DOM操作（搜索/滚动/抓取）
- Native Messaging 或 localhost WebSocket：与后端通信
- 健康检查：后端每10秒ping一次插件，判断是否在线

#### 5.2.3 方式B：uv run MCP（mcp_fetch_xhs_post，二次开发）

**启动方式**：`uv run main.py`，作为后端子进程或独立进程。

**实现基础**：基于社区 mcp_fetch_xhs_post 二次开发（D17决策），扩展支持搜索+发布+配图下载+风控策略。

**通信架构**：
```
服务器/本地终端
    └── uv run main.py（启动MCP server进程）
         ├── Playwright headless Chromium
         ├── 扫码登录拿Session（D1备选方案）
         ├── Session加密存DB，支持自动刷新
         └── 暴露MCP接口（stdio）给后端调用
```

**适用场景**：
- 开发联调（无需装插件，一条命令启动）
- 生产环境兜底（插件不在线时降级使用）
- CI/CD自动化测试

**风控应对**：
- 服务器IP建议走住宅代理池
- 单账号每日搜索≤20次
- 每次搜索间隔随机30-60秒
- 滚动节奏拟人化
- 遇滑块验证→暂停+切手动模式

#### 5.2.4 MCP Client Manager（统一入口 + 降级策略）

这是整个MCP集成的核心——后端只与Client Manager交互，不直接接触具体MCP实现。

```python
class MCPClientManager:
    """
    MCP统一入口，封装双模式降级策略
    对Agent暴露统一接口，Agent不感知底层是插件还是uv run
    """

    def __init__(self):
        self.plugin_client = PluginMCPClient()      # 方式A
        self.local_client = LocalMCPClient()         # 方式B
        self.current_mode: str = "plugin"            # plugin / local
        self.plugin_health: bool = False

    async def health_check_loop(self):
        """每10秒检查插件是否在线"""
        while True:
            self.plugin_health = await self.plugin_client.ping()
            if not self.plugin_health and self.current_mode == "plugin":
                await self._switch_to_local(reason="plugin_offline")
            await asyncio.sleep(10)

    async def search_notes(self, keyword: str, limit: int = 20) -> SearchNotesResult:
        """统一搜索接口，自动降级"""
        if self.current_mode == "plugin" and self.plugin_health:
            try:
                result = await self.plugin_client.search_notes(keyword, limit)
                return result
            except (ConnectionError, PluginNotRunning) as e:
                await self._switch_to_local(reason=f"plugin_error: {e}")
                # 降级后继续执行（不抛异常给上层）

        # 本地模式执行
        result = await self.local_client.search_notes(keyword, limit)
        return result

    async def fetch_post_detail(self, note_id: str) -> PostDetail:
        """统一获取笔记详情接口"""
        return await self._dispatch("fetch_post_detail", note_id=note_id)

    async def publish(self, content: PublishContent) -> PublishResult:
        """统一发布接口"""
        return await self._dispatch("publish", content=content)

    async def _dispatch(self, method: str, **kwargs):
        """统一调度：优先插件，失败降级本地"""
        if self.current_mode == "plugin" and self.plugin_health:
            try:
                return await getattr(self.plugin_client, method)(**kwargs)
            except (ConnectionError, PluginNotRunning):
                await self._switch_to_local(reason="plugin_error")
        return await getattr(self.local_client, method)(**kwargs)

    async def _switch_to_local(self, reason: str):
        """降级到本地模式，并通知前端"""
        self.current_mode = "local"
        # 推送SSE事件，前端提示用户
        await sse_broadcaster.broadcast(
            event_type="search_degraded",
            payload={
                "reason": reason,
                "message": "浏览器插件未运行，已降级到服务端搜索，风控较高",
                "suggest_install_plugin": True
            }
        )
```

#### 5.2.6 配图获取策略（D17决策）

**方式**：MCP返回图片base64（不返回URL，避免签名问题）。

**流程**：
1. MCP抓取笔记时，从DOM提取图片URL
2. MCP内部下载图片，转base64返回
3. 后端拿base64存临时文件，交给Qwen-VL分析
4. VL分析完成后，**立即删除临时文件**（符合D11"只分析不存储原图"）

**为什么不用URL直传Qwen-VL**：小红书图片URL有时效且需签名，直传不可靠。base64最稳定。

**为什么不用截图**：截图质量不稳定（受滚动/懒加载影响），base64是原图质量。

#### 5.2.7 登录态管理（D1调整：插件优先，扫码备选）

D1原决策"扫码登录+本地加密存储Session"调整为**分层登录策略**：

```python
class LoginManager:
    """登录态管理：插件优先，扫码备选"""

    async def ensure_login(self, account_id: str) -> LoginStatus:
        """
        确保登录态可用，按优先级尝试
        """
        # 1. 优先检查浏览器插件登录态（无需用户操作）
        if mcp_manager.plugin_health:
            status = await mcp_manager.plugin_client.get_login_status()
            if status.logged_in:
                return LoginStatus(
                    mode="plugin",
                    logged_in=True,
                    nickname=status.nickname,
                    message="使用浏览器登录态"
                )

        # 2. 插件不可用或未登录 → 降级到扫码登录
        token = await self._load_stored_token(account_id)
        if token and await self._is_token_valid(token):
            return LoginStatus(
                mode="local_token",
                logged_in=True,
                message="使用已存储的Session（扫码获得）"
            )

        # 3. Token过期或不存在 → 触发扫码登录
        return LoginStatus(
            mode="scan_required",
            logged_in=False,
            message="请扫码登录小红书",
            qrcode_base64=await self._generate_qrcode()
        )

    async def scan_login(self, account_id: str) -> str:
        """扫码登录，返回二维码base64"""
        result = await mcp_manager.local_client.login()
        return result["qrcode_base64"]

    async def save_token(self, login_id: str, user_id: str) -> None:
        """登录成功后，加密存储Refresh Token"""
        token_info = await mcp_manager.local_client.get_token(login_id)
        encrypted = aes_encrypt(token_info["refresh_token"], derive_key(user_master_pwd))
        await db.save_xhs_account(user_id, encrypted, ...)

    async def refresh_session(self, account_id: str) -> bool:
        """静默刷新Session（仅local模式需要，插件模式浏览器自动维护）"""
        token = await self._load_and_decrypt_token(account_id)
        result = await mcp_manager.local_client.refresh(refresh_token=token)
        if result["success"]:
            await self._save_encrypted_token(account_id, result["new_session"])
            return True
        return False
```

**登录态来源优先级**：
1. **浏览器插件登录态**（首选）：用户浏览器已登录，插件直接复用，零成本
2. **已存储的Session**（次选）：之前扫码拿到的Token，自动刷新
3. **扫码登录**（兜底）：Token失效时，引导用户扫码

**对D1的影响**：
- D1原方案"扫码登录"**降级为兜底方案**
- 装了插件的用户**完全无感**（浏览器已登录）
- 没装插件的用户走扫码（原有流程不变）

## 6. 监督Agent分散式守卫落地

### 6.1 四层落地位置

监督Agent以**分散式守卫**形态存在，散落在各节点边上。除了原有的三层（硬规则/软语义/状态机），新增 **Recovery 决策层**（解决崩溃恢复的循环需求）。

| 层 | 落地位置 | 触发时机 | 决策权限 | 成本 |
|---|---|---|---|---|
| Layer1 硬规则 | Harness.run() 内置 | 每个节点前后 | 二元判断（通过/不通过） | <10ms，零Token |
| Layer2 软语义 | graph中独立的quality_check_node | 仅分析/文案/审核节点之后 | 建议权（用户拍板） | 1次V3调用 |
| Layer3 状态机 | graph的conditional_edges路由 | quality_check之后 | 硬编码路由 | 零 |
| Layer4 Recovery决策 | recovery/supervisor.py | Recovery Loop三次策略全失败时 | 分层决策（见6.4） | 1次V3调用（仅结构性恢复） |

### 6.2 软语义判断节点

```python
async def make_quality_check_node(node_type: str):
    """
    软语义判断节点工厂
    仅对质量敏感节点生效：analyze/copywrite/audit
    """
    async def quality_check(state: WorkflowState) -> dict:
        node_output = state["outputs"].get(node_type)
        if not node_output or node_output.status != "passed":
            return state  # 节点本身失败，不进入软语义

        # 调用轻量LLM做质量判断（D3: 只判质量不控制流程）
        config = get_agent_config(node_type)
        if not config.soft_semantic_config or not config.soft_semantic_config.enabled:
            return state  # 该节点未启用软语义

        judge_prompt = build_judge_prompt(
            check_points=config.soft_semantic_config.check_points,
            node_output=node_output,
            theme=state["theme"]
        )

        judge_result = await deepseek_v3.chat([
            {"role": "system", "content": JUDGE_SYSTEM_PROMPT},
            {"role": "user", "content": judge_prompt}
        ])

        quality_report = parse_judge_result(judge_result)
        # {quality_pass: bool, issues: [], severity: "low/medium/high"}

        # 写回节点产出（不直接路由，路由由conditional edge决定）
        node_output.quality_report = quality_report

        # 记录监督决策日志
        await log_supervisor_decision(
            workflow_id=state["workflow_id"],
            node=node_type,
            layer="soft_semantic",
            quality_pass=quality_report["quality_pass"],
            issues=quality_report["issues"],
            model="deepseek-v3"
        )

        return {"outputs": state["outputs"]}
    return quality_check
```

### 6.4 Recovery 决策层（Layer4，分层决策）

当 Agent 内部 Recovery Loop 三次策略全失败，触发 `escalate_to_supervisor=True`，进入 Recovery 决策层。**采用分层决策机制**（决策2）：

| 恢复类型 | 例子 | 决策权限 | 是否打断用户 |
|---|---|---|---|
| **技术性恢复** | 切换备用模型（R1→V3）、刷新Token、调参 | **自动执行** | 否 |
| **结构性恢复** | 回退到上游节点重跑 | **用户拍板** | 是 |
| **无法恢复** | 所有方案都试过仍失败 | **终止+告警** | 是 |

```python
from enum import Enum

class RecoveryActionType(Enum):
    TECHNICAL_RETRY = "technical_retry"      # 技术性：自动执行
    STRUCTURAL_ROLLBACK = "structural_rollback"  # 结构性：用户拍板
    TERMINATE = "terminate"                  # 终止

class RecoveryAction:
    action_type: RecoveryActionType
    target_node: str | None       # 结构性回退的目标节点
    technical_params: dict        # 技术性恢复的参数（如换模型）
    reason: str
    require_user_confirm: bool    # True=用户拍板；False=自动执行
    timeout_seconds: int = 1800   # ★ 结构性恢复30分钟超时

async def supervisor_recovery_decision(
    crashed_node: str,
    crash_reason: str,
    crash_context: dict,
    state: WorkflowState
) -> RecoveryAction:
    """
    监督Agent恢复决策（Layer4）
    只在Agent内部Recovery Loop耗尽后才触发
    根据崩溃原因分类决策
    """
    # === 技术性恢复：自动执行，不打断用户 ===
    if crash_reason in ("model_overload", "model_timeout", "rate_limit"):
        # 模型过载/限流 → 切备用模型，本地重试
        return RecoveryAction(
            action_type=RecoveryActionType.TECHNICAL_RETRY,
            target_node=crashed_node,
            technical_params={"force_model": "deepseek-v3"},
            reason=f"模型过载，自动切换到V3重试",
            require_user_confirm=False   # ★ 技术性：自动执行
        )

    if crash_reason == "token_expired" and crashed_node == "publish":
        # Token过期 → 自动刷新后重试
        return RecoveryAction(
            action_type=RecoveryActionType.TECHNICAL_RETRY,
            target_node=crashed_node,
            technical_params={"refresh_token_first": True},
            reason="Token过期，自动刷新后重试",
            require_user_confirm=False
        )

    # === 结构性恢复：用户拍板 ===
    if crash_reason == "input_insufficient" and crashed_node == "analyze":
        # 分析输入不足 → 建议回退到搜索
        return RecoveryAction(
            action_type=RecoveryActionType.STRUCTURAL_ROLLBACK,
            target_node="search",
            reason="分析输入不足，建议回退到搜索重新获取爆款",
            require_user_confirm=True,    # ★ 结构性：用户拍板
            timeout_seconds=1800          # 30分钟超时
        )

    if crash_reason == "image_gen_failed" and crashed_node == "image_gen":
        # 图片生成失败 → 建议回退到分析（重新生成视觉标签）
        return RecoveryAction(
            action_type=RecoveryActionType.STRUCTURAL_ROLLBACK,
            target_node="analyze",
            reason="图片生成持续失败，建议回退到分析调整视觉标签",
            require_user_confirm=True,
            timeout_seconds=1800
        )

    # === 无法恢复：终止 ===
    return RecoveryAction(
        action_type=RecoveryActionType.TERMINATE,
        reason=f"无法恢复的崩溃: {crash_reason}",
        require_user_confirm=True,
        timeout_seconds=1800
    )
```

### 6.5 30分钟超时挂起机制（决策2补充）

**触发场景**：结构性恢复需用户拍板，但用户30分钟内未响应。

**行为**：不永久阻塞，自动挂起任务，释放资源，下次定时拉起。

```python
class StructuralRecoveryTimer:
    """
    结构性恢复的30分钟超时管理器
    超时后自动挂起工作流，释放资源
    """

    TIMEOUT_SECONDS = 1800  # 30分钟

    async def start(self, workflow_id: str, target_node: str):
        """启动超时计时器"""
        await db.save_pending_recovery(
            workflow_id=workflow_id,
            target_node=target_node,
            started_at=datetime.utcnow(),
            expires_at=datetime.utcnow() + timedelta(seconds=self.TIMEOUT_SECONDS),
            status="waiting_user"
        )
        # 注册定时任务，超时触发suspend
        scheduler.add_job(
            self._check_and_suspend,
            "date",
            run_date=datetime.utcnow() + timedelta(seconds=self.TIMEOUT_SECONDS),
            args=[workflow_id],
            id=f"suspend_{workflow_id}"
        )

    async def _check_and_suspend(self, workflow_id: str):
        """超时检查：若用户仍未响应，挂起工作流"""
        pending = await db.get_pending_recovery(workflow_id)
        if pending and pending.status == "waiting_user":
            await self._suspend_workflow(workflow_id, pending)

    async def _suspend_workflow(self, workflow_id: str, pending: PendingRecovery):
        """
        挂起工作流
        - 状态改为 suspended
        - 释放Worker资源（LangGraph图暂停）
        - 记录恢复点，供下次拉起
        - 通知用户
        """
        # 1. 工作流状态改为suspended
        await db.update_workflow_status(workflow_id, "suspended")

        # 2. 保存恢复点（含pending recovery信息）
        await db.save_suspend_point(
            workflow_id=workflow_id,
            pending_recovery=pending.to_dict(),
            langgraph_thread_id=pending.langgraph_thread_id,
            suspended_at=datetime.utcnow()
        )

        # 3. 释放Worker资源（取消当前task）
        await workflow_worker.cancel(workflow_id)

        # 4. 通知用户
        await ws_manager.broadcast(workflow_id, {
            "type": "workflow_suspended",
            "reason": "structural_recovery_timeout",
            "message": "30分钟未响应，任务已挂起，下次定时检查时自动拉起",
            "pending_node": pending.target_node,
            "can_resume_manually": True   # 用户可随时手动恢复
        )

        # 5. 注册定时拉起任务（每小时检查一次）
        scheduler.add_job(
            self._try_resume_suspended,
            "interval",
            hours=1,
            args=[workflow_id],
            id=f"resume_check_{workflow_id}"
        )

    async def _try_resume_suspended(self, workflow_id: str):
        """
        定时尝试拉起挂起的工作流
        - 检查依赖是否恢复（如模型是否可用）
        - 若依赖OK → 重新拉起，进入待用户确认状态
        - 若依赖仍不可用 → 继续挂起
        """
        suspend_point = await db.get_suspend_point(workflow_id)
        if not suspend_point:
            scheduler.remove_job(f"resume_check_{workflow_id}")
            return

        # 检查崩溃原因是否已恢复
        dependency_ok = await self._check_dependency_recovered(suspend_point)

        if dependency_ok:
            # 重新拉起，回到待用户确认状态
            await db.update_workflow_status(workflow_id, "awaiting_user_recovery")
            await db.update_pending_recovery_status(workflow_id, "waiting_user")

            await ws_manager.broadcast(workflow_id, {
                "type": "workflow_resumed_pending",
                "message": "任务已拉起，等待您确认结构性恢复方案",
                "pending_node": suspend_point.pending_recovery["target_node"]
            })

            # 重新启动30分钟超时计时器
            await self.start(workflow_id, suspend_point.pending_recovery["target_node"])

            # 取消定时拉起任务
            scheduler.remove_job(f"resume_check_{workflow_id}")

    async def user_manual_resume(self, workflow_id: str):
        """用户手动恢复挂起的任务"""
        await self._try_resume_suspended(workflow_id)
```

### 6.6 整体循环结构（监督-修复闭环）

```
节点执行
  │
  ▼
Recovery Loop（Harness内，max_attempts=3，含退避+熔断）
  │ 策略1: 原样重试
  │ 策略2: 调整输入/参数（拓宽关键词/减少输入/简化prompt）
  │ 策略3: 切备用模型
  │
  ├─成功→返回，熔断器记录成功
  │
  └─全失败→escalate_to_supervisor=True
              │
              ▼
          Recovery 决策层（Layer4）
              │
              ├─技术性恢复（模型过载/Token过期）
              │   → 自动执行，不打断用户
              │   → 本地重试（不回退节点）
              │
              ├─结构性恢复（输入不足/链路问题）
              │   → 建议权，用户拍板
              │   → 启动30分钟超时计时器
              │   │   ├─用户确认 → rollback_to_node() 跨节点回退
              │   │   ├─用户忽略 → 继续（标记问题）
              │   │   └─30分钟超时 → 挂起任务，释放资源
              │   │                   ↓
              │   │                定时拉起检查（每小时）
              │   │                   ↓
              │   │                依赖恢复 → 重新进入待确认
              │   │                依赖未恢复 → 继续挂起
              │   │
              │   → 用户可随时手动恢复
              │
              └─无法恢复 → 终止+告警，用户拍板
```

**三层兜底，避免死循环**：
1. Recovery Loop：max_attempts=3 上限
2. 熔断器：failure_threshold=5 触发熔断，60秒后半开试探
3. 30分钟超时挂起：不永久阻塞，资源释放，定时拉起

## 8. 横切关注点

### 8.1 任务内上下文（Memory）

D7决策：仅任务内上下文，不做跨任务记忆。

```python
class TaskContext:
    """任务内上下文，随WorkflowState流转，不持久化跨任务"""
    workflow_id: str
    theme: str
    # 通过LangGraph的State自动在节点间传递，无需额外Memory模块
```

上下文传递完全依赖LangGraph的`WorkflowState`，每个Harness通过`context: WorkflowState`参数读取上游产出，无需自建Memory系统。

### 8.2 可观测性

### 8.3 错误处理边界

| 错误类型 | 处理层 | 行为 |
|---|---|---|
| 超时/空返回/HTTP错误 | Layer1硬规则 | 重试3次→标记error |
| Schema校验失败 | Layer1硬规则 | 重试1次→标记error |
| 软语义不通过 | Layer2 | 建议回退（用户确认） |
| MCP服务不可用 | 健康检查 | 节点直接error，告警 |
| Token失效 | 发布Agent前置检查 | 中断，提示重新扫码 |
| LangGraph checkpoint损坏 | 编排层 | 工作流terminated，记录日志 |

## 10. 研发实施建议

### 10.1 实施顺序

1. **搭骨架**：backend目录结构 + FastAPI启动 + DB迁移
2. **MCP服务**：基于xiaohongshu-mcp-py封装，跑通扫码登录+搜索+发布
3. **适配器层**：DeepSeek/Qwen-VL/通义万相适配器

5. **LangGraph图编排**：先跑通search→analyze两节点+软语义
6. **逐个Agent补全**：按search→analyze→image_gen→copywrite→audit→publish顺序
7. **人工审核interrupt**：接入image_review和final_review
8. **回退服务**：基于checkpoint实现
9. **WebSocket推送**：状态变更广播
10. **前端**：账号绑定 → 流程图 → 审核 → 回退
