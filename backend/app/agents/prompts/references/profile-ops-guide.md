# 画像操作指南

profile-builder 和 profile-manager 的操作规范。

## builder vs manager 职责边界

| 操作 | 归属 | 说明 |
|------|------|------|
| 从零生成画像 | profile-builder | 首次引导，收集信息+分析+综合成稿 |
| 创建空白画像 | profile-manager | 只建骨架，不引导分析 |
| 编辑字段 | profile-manager | 修改已有画像的某个维度 |
| 更新记忆 | profile-manager | 追加运营洞察到 memory |
| 切换画像 | profile-manager | 多画像间切换激活 |
| 导出画像 | profile-manager | 合并六维为一份摘要 |
| 对比画像 | profile-manager | 两个画像逐维对比 |

## 画像存储策略

画像存 LLM 上下文（Chat 会话内），不存文件系统：

- **优势**：零文件系统依赖，Chat 天然有上下文，画像随会话可用
- **劣势**：跨会话不持久（但用户可随时让 manager 导出，粘贴到下次会话）
- **实现**：builder 生成画像后输出完整结构化文本，用户可复制保存；manager 的 edit/memory-update 在当前会话内修改画像上下文

## 引导提问原则

1. **分组问**：一次问一组（3-4题），别一口气抛14题
2. **给例子**：每个问题附带示例，降低回答门槛
3. **允许留白**：用户说"不知道"就标 `[待补充]`，不逼问不编造
4. **先分析再对齐**：能从 trending_search 推断的，先出结论让用户确认，而非干问
5. **小红书优先**：默认平台是小红书，相关问题放最前

## 信息降级策略

当无法直接获取数据时，按优先级降级：

1. **用户自述** — 最可靠，直接采纳
2. **trending_search 辅助** — 搜赛道热点推断受众偏好，标注 `[推断待确认]`
3. **对标账号推断** — 用户给参考账号，从其内容推断风格/受众，标注 `[推断待确认]`
4. **留白** — 实在拿不到就 `[待补充]`，绝不臆造

## 画像完整度计算

6 个维度文件，每个有实质内容（非空非模板）= 1/6 ≈ 16.7%

| 完整度 | 判断 |
|--------|------|
| 100% | 6维全部有实质内容 |
| ≥80% | 可用于 account-diagnosis 和 persona-check |
| ≥50% | 可用于部分策略 Skill，但建议补充 |
| <50% | 信息不足，建议先跑 builder 补全 |

## 小红书特化引导

在标准引导问题之外，针对小红书场景额外问：

1. 你的种草力定位是什么？（种草型/拔草型/测评型/知识型）
2. 主力笔记类型？（教程/好物分享/对比测评/空瓶记/合集/探店）
3. 封面偏好风格？（对比图/手写体/大字报/真人出镜/产品拼图）
4. 目标受众的收藏习惯？（小红书用户收藏率远高于点赞率）
