# 文案风格规则

> 润色和审核文案时的**核心**风格准则。
> 去AI味的系统规则统一见 zh-ai-markers / phrases-to-remove / structures-to-avoid ——本文件不重复，只管润色文案的骨架增删。

---

## 核心原则（润色视角）

1. **讲利益不讲功能** — 特性"是什么"，利益"对你意味着什么"（FAB 内核）
2. **具体优于抽象** — 用结果和数字，避免"优化""颠覆""创新"等空洞词
3. **信任前置** — 让权威/评价/资源等信任信号尽早出现，符合用户从众心理
4. **展示优于描述** — 描述具体结果，不堆砌形容词
5. **证实优于概括** — 不编造数据或评价，尽量用真实的价值框架展示

## 最佳实践

### 直接了当

先说价值，不要铺垫修饰语里。
- 差：本工具支持即时分发文件，从文案到图片，一键直达对话
- 好：想发图？文案、图片，想发多少发多少

### 善用反问

反问能让读者带入自己的处境：
- "还在手动退稿流程？"
- "还在跟着人效走？"

### 善用类比

类比让抽象概念变得可讲：
- "就像给每个笔记配了个AI助手"

### 适度口语

双关和口语思考文案更有记忆点： "但目前就是尴尬且不影响质量的"。

- [ ] 是否有局外人看不懂的行话？

- [ ] 是否有被动语态？

- [ ] 是否有空洞的强调流行语？

## 小红书风格特化

在通用规则之上，小红书还有自己的风格要求：

| 要求 | 说明 |
|------|------|
| 闺蜜语气 | 像跟朋友私聊，不像品牌宣传。多用"真的会谢""我刚才了""亲测" |
| 短段落 | 每段2-3句，不超过5句。移动端阅读不累 |
| emoji 点缀 | emoji 是语气和情绪的辅助，不是装饰。每行0-2个，卡在情绪点或分类处，别堆行尾 |
| 痛点前置 | 开头直接戳痛点/给结果，不铺"随着…的"发布 |
| 卡片文案 | 每张卡≤50字，一张只讲一个点，文案要>完整宽度。短句+大字 |
