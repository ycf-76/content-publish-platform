# 2026-10-10

## 梳理项目 Skills 与执行层架构（大哥问"skills 用不了"根因）

关键结论（已写成 `outputs/skills_execution_layer_analysis.md`）：

- 项目 skills 分两套，极易混淆：
  1. **提示词型 `PromptDrivenSkill`**：`backend/app/agents/prompts/skills/*.md`，共 65 个。
     `execute()` 只把 md 当 prompt 喂 LLM，返回文本/HTML。**执行层只有 LLM（model_router）**，
     只要 LLM 通就永远能跑。卡片类可回调 `card_image_gen` 生图（需 dashscope key）。
  2. **代码型 `Skill` 子类**：`backend/app/tools/` 的 `BUILTIN_SKILL_MODULES`，共 14 个，
     各自依赖外部执行层（API key / Playwright 登录态 / 飞书凭证 / 微信 RPA / ffmpeg 等）。
- **`video_script` / `voice_builder` 全是提示词型**——只产出脚本/画像文本，不渲染视频、不合成语音。
  "视频用不了"根因不是 skill 坏，是缺把脚本→视频的执行层编排。
- 视频/语音执行层三层栈现状：① TTS（piper 仅在 `dev_tools` 白名单当手动命令，未封装成 Skill，无语音模型）
  ② 图生视频（即梦/可灵未接入）③ 视频合成（`ffmpeg` 同理只在白名单；全仓无 `video_compose`/`openmontage`/`moviepy` 接成 Skill）。
  → 需新建 `produce` 视频代码型 Skill 串 TTS+生图+ffmpeg。
- 缺 key/登录态导致"用不了"的：生图/视觉(`DASHSCOPE_API_KEY`)、搜索(`SERPER_API_KEY`)、
  XHS 搜索/评论(刷新 `storage_states`)、飞书(app 凭证)、微信(RPA 登录态)。
- 小坑：`comment-insights.md` 与 `comment_insights.py` 同名同 node_type，运行时后者覆盖前者。

## 修复「TTS 没被 Agent 识别为可用工具」

**症状**：Agent 说"没有语音合成能力"。两个根因叠加：

1. **缺依赖**：venv 没装 `edge_tts` → `app/skills/produce/tts.py` import 失败 → `@register` 没跑
   → `tts_edge` 根本没进 SkillRegistry。已装 `edge_tts==7.2.8`。
2. **白名单漏配（主因）**：`app/agents/registry.py` 的 `CREATION_TYPE_SKILLS` 是硬编码白名单，
   请求只要带 `creation_type`（**前端每次都传**），Agent 工具表就只保留白名单内的 Skill。
   `tts_edge` 没写进任何创作类型 → 被静默丢弃。

**修复**：新增 `ALWAYS_LOAD_CAPABILITY_SKILLS`（`tts_edge`/`url_collect`/`meme_render`/
`wechat_send_*`/`feishu_*`），在 `_resolve_creation_type_skills()` 里与 `ALWAYS_LOAD_SKILLS` 一起合并；
另加 `_audit_skill_coverage()` 启动审计，把「已注册但白名单覆盖不到」的 Skill 打 warning，
防止以后新增 Skill 再犯同样错误。

**实测**：7 种场景（全量 + 6 种 creation_type）`tts_edge` 全部在工具表内；
端到端 `TTSSkill().execute()` 产出 40752 字节 `outputs/tts_output.mp3`。

## 关键机制（下次排查"Agent 说没这能力"必看）

链路：`SkillRegistry`（注册）→ `_build_skills(agent_def.skills, creation_type)`（过滤）
→ `harness.skills` → `LoopExecutor._build_tools_schema()`（转 function calling）
→ **`_MAX_TOOLS_FOR_LLM = 65` 截断，顺序 triggered→hot→warm→cold**。

实测数据：全量注册 **90** 个（含 `backend/skills/` 第三方扫描），优先级分布 hot 37 / warm 36 / cold 17。
全量场景会截断到 65：`tts_edge` 是 warm 且排 warm 队列第 3 位，**能存活**；但 cold 会被全砍。

**注意**：只 import `BUILTIN_SKILL_MODULES` 统计到的只有 25 个，必须再跑
`registry.scan_third_party()` 才是真实全量 90 个 —— 排查时别漏。

**目前 35 个已注册 Skill 白名单覆盖不到**（`video_script`、`video_strategy`、`chart_visualization`、
`mindmap`、`novel_writer` 等），带 creation_type 的请求里 Agent 看不到它们 —— 这大概率就是
大哥说的"继承了很多 skills 都用不了"的**另一半根因**。要彻底解决得重做 `CREATION_TYPE_SKILLS` 覆盖面。
