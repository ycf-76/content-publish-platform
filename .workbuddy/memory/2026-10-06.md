## 深夜：修「流程已结束但顶部一直转圈说正在搜索热点」

大哥问：搜索都完成了，为什么状态行还显示在调用 LLM 搜索，是不是在烧 token？

**答案：不烧。** UI 转圈是 `ToolCallCell.isAnyRunning` 这个纯 computed，读本地数组的 status 字段，
不发任何网络请求；后端那一轮也已 `workflow_error`/`agent_error` 终止（截图底部「处理出现问题」）。
真烧 token 的 agent loop 已经停了。

**根因（前端配对 bug，不是后端丢事件）**：
`useChatSSE.ts` 的 `case 'tool_call_end'` 原写法：
```js
let target = assistantMsg.toolCalls?.[assistantMsg.toolCalls.length - 1]
if (target && target.name !== endToolName) { 反向查找 ... }
```
先无条件取「最后一个 toolCall」，只在**名字不符**时才回退搜索——**没校验 subAgentId 也没校验 status**。
两个子智能体并发调用同名工具（截图里两个都叫「搜索热点」，都调 trending_search）时，
A 的结束事件会记到 B 头上，A 永远卡在 running。

**证据**：后端日志按节点统计 start/end —— `sub:0e19b81625b8` 是 **9 start / 9 end 完全平衡**，
`9379c2a3e52c` 14/14，`741307dcc80e` 4/4，`dc99959a8100` 1/1。事件齐的，问题在前端配对。

**修复**：
1. `useChatSSE.ts`：匹配改为严格 FIFO —— `calls.find(tc => tc.name===end && tc.subAgentId===sub && tc.status==='running')`
2. `useChatSSE.ts` 新增 `_settleOrphanToolCalls(msg, reason)` 兜底清算，调用点：
   `workflow_error`/`workflow_failed`、`workflow_cancelled`、`agent_error`、两条 SSE 链路的**重试耗尽**分支。
   **故意不在 `workflow_completed` 调用** —— chat 模式下 workflow 结束不代表本轮工具调用结束。
   也故意不在 AbortError 上调用（会话切换/卸载会误伤）。
3. `cell-types.ts`：`ToolCall.status` 增加 `'aborted'` 终态。语义是「本轮已终止，结果没回传，不知道成没成」，
   和 `error`（工具确实失败）区分开——混用会让状态行误报「遇到问题」。
4. `ToolCallCell.vue`：`CellState` 加 aborted；`STATE_RANK` 改 running4/error3/aborted2/pending1/done0；
   `isSettled()` 统一判定；`iconForStatus` 加 `CircleSlash`（灰）；状态行在有 aborted 时追加
   `（N 项结果未回传）`，不粉饰成「已完成」。
5. `icon-map.ts`：补 `trending_topics` → 搜索热点（截图里这个漏了显示成英文）。

验证：`vue-tsc -b` 通过（第一次漏改 `CellState` 报 TS2678，已补）；`vite build` OK；
dev server 抓 `useChatSSE.ts` 能 grep 到 `_settleOrphanToolCalls` 和 `aborted`；vite 日志 ERROR 0。
