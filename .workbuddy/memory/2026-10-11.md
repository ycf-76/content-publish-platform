# 2026-10-11

## CREATION_TYPE_SKILLS 白名单重构：过滤器 → 排序器

承接昨天（10-10）TTS 修复。大哥问「白名单指什么、怎么改、你拍板」，我拍了 **方案 B**。

### 白名单是什么

`backend/app/agents/registry.py` 的 `CREATION_TYPE_SKILLS`：按创作类型手工罗列技能名，
`_build_skills()` 查表后**只放行名字在集合里的技能**。前端每次请求都带 `creation_type`。
数据：白名单覆盖 55 个名字（全部真实，无拼写错误），注册表 90 个 → 差 35 个孤儿。

### 选型

- A 补全白名单：雷还在，新增技能仍会漏配
- **B 降级为排序器（采纳）**：不过滤，命中排前面 → 注册即可见 + 保留任务相关性优先
- C 直接废弃：当前任务相关的 cold 技能会被无关 hot 挤掉

### 改动

1. `app/agents/registry.py` `_build_skills()`：过滤改排序（`hit + miss`），删掉 `_hot_create_names` 补丁
2. `app/agents/registry.py` `_audit_skill_coverage()`：漏配只告警"丧失排序优先级"；
   新增**反向审计**「白名单写了但注册表没有的名字」（实测幽灵数 = 0）
3. `app/engine/harness/executor/loop.py`：路由前移到 `_build_tools_schema()` 之前

### 顺手修掉的隐藏 bug：triggered 队列是死代码

`execute()` 里 `_build_tools_schema()` 在 L362 跑完并缓存进 `_tools_schema_cache`，
而路由（算 trigger_words 命中）在 L1188 才执行 → 建表时 `_routing_result` 永远是 None
→ **triggered 队列永远为空，trigger_words 的"点名保命"形同虚设**，
65 上限截断时用户点名要的冷门技能照样被砍。修法：建表前先跑一次 `select_skills()`。

### 验证（离线 + 线上）

7 种场景全部 90 → 65，`tts_edge`/`video_script`/`mindmap` 等昔日孤儿全部可见；
voiceover 白名单命中存活率 17/17 = 100%；
triggered 修复：`meme_render`、`doc_convert` 从 ❌ 变 ✅。
线上日志实测 `whitelist_hit=55, others=35`，审计告警正常。

### 代价

工具数从每请求约 49 涨到 65（截断上限），prompt token +约 1600。
若想省，可下调 `_MAX_TOOLS_FOR_LLM`——有了 triggered 保命，缩小上限是安全的。
